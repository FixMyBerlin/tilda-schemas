## Riding direction (tilda-geo-private#34)

Branch commits `27e2cbe40`, `82bbf0d94`, `4fb14e1c5` (review notes in `docs/oneway-direction-review.md` there). Ported:

- `derive_oneway.lua`: `yes`/`1` and `-1` (also `oneway:bicycle=-1`) are an explicit `oneway=yes`; lanes and tracks on the road without
  `cycleway:<side>:oneway` are `implicit_yes` with the side default direction (right with the way, left against it;
  `oneway=yes` roads: both with the way; `oneway:bicycle=no` makes the left lane the contraflow lane; `oneway=-1` mirrored);
  an explicit side tag against the default is followed literally. Result `_lineReversed` is `_line_reversed`.
- `extract_bikelanes.lua`: `offset` relative to the published line.
- `transform_cycleway_opposite_schema.lua`: `oneway=-1` mirrored, explicit `cycleway:<side>:oneway`.
- `bikelane_categories.lua`: `not_expected` on the right side of `oneway=-1` roads.
- `transformations.lua`: `traffic_sign:backward` for a separate way with `oneway=-1`.
- `bikelane_todo_categories.lua`: `unexpected_oneway_direction` with `todoTagFixes`, and `missing_oneway` no longer for lanes on the road.
- Lua tests `derive_oneway.test.lua`, `bikelanes_oneway_direction.test.lua`, `transform_cycleway_opposite_schema.test.lua` became
  `test/derive-oneway.test.ts`, `test/transform-cycleway-opposite-schema.test.ts` and the fixtures in
  `schemas/bicycle-infrastructure-attributes/fixtures/{oneway,transformation,todos}`.

Not ported (no counterpart in the package): `bikelanes_presence` (`oneway=-1`), the routing table, `orient_line_direction_tags`
(swaps `traffic_sign:forward|backward` and `mapillary_*`, which the package does not output), MapRoulette campaign and tag-fix plumbing, map styles.

## Other decisions

- **Units of `width`.** The task text said "cm/m/mm/ft/in as LUA does". LUA converts only `cm`, `m` and `km`; `mm`, `ft`, `in`, `mi` and
  everything else gives no width (`parse_length.test.lua` lists `2 mm`, `3 ft`, `6'` as unreadable). The package does what LUA does.
- **Todos are new in the package.** There was no todo code before. `src/derive/bikelane-todos.ts` ports every todo of
  `bikelane_todo_categories.lua` that only needs OSM tags. Left out: the `*__mapillary` variants and the priority (Mapillary pseudo
  tag), `currentness_too_old` (object timestamp), `adjoining_of_vs_csv` (sidepath CSV). The todos of a road (`road_todo_categories.lua`: `deprecated_cycleway_shared`, `unusual_width`) are in `src/derive/road-todos.ts`, with `fixtures/road-todos`.
- **`parking=no`** gives no traffic mode: the package already did that; now pinned by `fixtures/traffic-mode`.
- **Protective `separation` set** of `cyclewayOnHighwayProtected` (`bollard`, `flex_post`, `vertical_panel`, `studs`, `bump`, `planter`,
  `fence`, `jersey_barrier`, `guard_rail`): the package already matched; now pinned by category fixtures for each value, in and out.
- **Decision view.** LUA removed it (`df5a54bed`). The package keeps its Proxy, which behaves the same; see the table.

## Probable LUA bugs and questions (not "fixed" in the package)

1. `missing_segregated` has `(object_tags.segregated ~= 'yes' or object_tags.segregated ~= 'no')`, which is always true. Probably `and`.
   Effect is small (`needsClarification` with `segregated=yes|no` is rare), the package copies it.
2. `highway=cycleway` + `traffic_sign=none` (`98e649800`) also matches a side object of a road that is tagged only with sub-keys, for example
   `cycleway:right:lane=advisory` + `cycleway:right:traffic_sign=none` + `cycleway:lanes=no|no|lane|no` (a "Radweg in Mittellage" with the lane tagged
   twice). The `needsClarification` category skips those on purpose ("HACK" for `cyclewayOnHighwayBetweenLanes`), the new rule has no such guard,
   so Berlin gets 3 extra `cycleway_adjoining` features (ways 1207199791, 529891428, 1442781274). Probably the new case needs
   `not has_cycleway_on_highway_between_lanes_conditions(tags)` like `needsClarification`.
3. Oneway branch: every lane on the road without a side tag is `implicit_yes`, also `sharedMotorVehicleLane` (`cycleway:right=shared_lane`),
   whose category says `implicitOneWay = false` ("the whole road is shared"). `missing_oneway` is gone for them. Intended?
4. `missing_access_tag_240` says "Expected `bicycle=designated` and `foot=designated`", but the condition is `bicycle ~= 'designated' and foot ~= 'designated'`: it
   triggers only when neither is designated, so `traffic_sign=DE:240` with `bicycle=designated` and no `foot` gets no todo. Probably `or`. Copied.
5. `deprecated_cycleway_shared` reads only `cycleway=shared`, but `needs_clarification` skips every side object with `cycleway=shared` ("handled by the road
   todo"). `cycleway:right=shared` and `cycleway:both=shared` give no bikelane feature and no road todo, so nothing flags them. Found while porting the road todos.
6. Cosmetic: the `unexpected_highway_path` text says `highway=cyclway`.

Not bugs, but good to know: `parse_length` reads only the exact decimal-comma strings `0,3 0,5 0,6 1,5 2,2 2,5 2,50` (use count in Germany above 10), so `2,0` or
`1,50` stay unreadable and show up as `unusual_width`; and a check date on the road closes `unusual_width` for all its lanes.
